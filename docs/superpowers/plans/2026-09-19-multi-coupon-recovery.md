# 다중 쿠폰 처리 후속 개발

## 목표와 역할

기존 미커밋 구현을 보존하고 사용자가 제공한 두 스크린샷을 각각 2개/3개 쿠폰으로 저장한다. 메인 에이전트가 통합 검증과 검토를 담당하고 GPT-5.6 Sol 작업자가 인식 및 저장 흐름을 나눠 수정한다. 저장소 변경은 커밋하지 않는다.

## 확인된 시작 상태

- 다중 바코드 검색, 좌표 있는 OCR, 쿠폰 분리, 공유 원본, DB v2 마이그레이션, 원본 영역 UI가 이미 구현되어 있다.
- 기존 단위 테스트 및 APK 빌드는 통과하지만 실제 두 이미지 통합 테스트에서 사용처가 null인 쿠폰이 발생했다.
- 저장 단계가 원자적이지 않아 실패 후 원본 파일만 지워질 수 있다.
- 상세 재인식이 분리된 쿠폰 영역 대신 전체 스크린샷을 읽는다.
- 웹 조회는 발행사 웹페이지를 여는 수동 조회다. 인증된 자동 조회 API가 아니다.

## 실행 및 검증

- [ ] 인식: 잘린 브랜드 헤더, EVENT 태그, 중복 코드, 잘린 이웃 카드 및 단일 쿠폰 회귀 수정.
- [ ] 저장: 원본/쿠폰/바코드 트랜잭션, 취소 전파, 동시 중복 처리, 영역별 재인식 수정.
- [ ] 단위 테스트/Android 테스트 APK/본 APK/Lint 검증.
- [ ] 실제 두 이미지에서 각각 2개/3개, 총 5개, 각 사용처/종료일 연결 및 재수입 0개 추가 확인.
- [ ] 마이그레이션/실패 롤백/다른 만료일 재인식 회귀 검증.
- [ ] 에뮬레이터 최종 APK 업데이트와 원본 영역/전체 이미지/바코드 확인.

## 웹 연동

검색 API 및 발행사 제휴 API 준비 여부를 사용자에게 문의한다. 비밀키를 채팅/로그/저장소에 넣지 않는다. 인증 정보와 허용 범위 없이 자동 조회 완료를 주장하지 않는다. 현재 다중 쿠폰 오류 수정은 답변과 독립적으로 진행한다.

## 입력 자료

실제 쿠폰 PNG는 사용자 Downloads 및 에뮬레이터 캐시에만 둔다. 이미지/전체 쿠폰 번호는 저장소나 검증 보고서에 복사하지 않는다. 테스트에는 파일 경로를 실행 인자로 전달한다.
