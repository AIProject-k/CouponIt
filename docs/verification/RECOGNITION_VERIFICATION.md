# 인식 구조 검증 (좌표 기반 필드 추출)

검증일: 2026-09-20. 환경: Windows, Zulu JDK 21, FaceScope_API36 에뮬레이터(API 36).

## 배경

사진이 바뀔 때마다 예외 규칙을 덧붙이는 방식으로는 새 양식을 감당할 수 없었다.
이전 파서는 OCR 결과를 한 덩어리 문자열로 합친 뒤 정규식으로 해석해, 다음이 구조적으로 막혔다.

- 브랜드 목록에 없는 사용처(예: `버거킹`)를 읽지 못함. 이전 버거킹 이미지는 `[버거킹]` 형식 덕에 통과했을 뿐이다.
- `(버거킹) 상품명`처럼 괄호 종류가 다르거나 상품명이 여러 줄이면 뒷줄이 잘림
- 날짜와 `까지 사용`이 서로 다른 OCR 줄로 나뉘면 종료일을 놓침

## 바뀐 구조

```
OCR(좌표 유지) → 같은 줄 묶기(rows) → 필드 추출(CouponLayoutParser)
      → 부족하거나 낯설면 해당 영역만 확대·흑백으로 재인식
      → 두 결과 대조(reconcile) → 충돌 필드는 확정하지 않고 확인 대상으로
```

- 좌표를 해석 단계까지 유지한다. 같은 문단으로 이어지는 여러 줄을 상품명으로 묶고, 날짜·주문번호는 분리한다.
- 브랜드 사전은 이름 표준화에만 쓰고, 사전에 없다고 버리지 않는다.
- 바코드 아래 인쇄된 번호와 디코딩 값이 다르면 확인 대상으로 남긴다. 값을 덮어쓰지 않는다.
- 필드마다 근거가 된 원문 줄을 남겨 상세 화면에서 그 영역을 볼 수 있다.


`CouponRecognitionCorpusTest`의 G마켓 게이트는 `gmarketPath`가 없으면 **건너뛰지 않고 실패**한다.
실제 이미지 평가를 생략한 채 전체 통과라고 보고하지 않기 위해서다. 이미지는 저장소에 넣지 않으므로
새 클론에서 계측 테스트 전체를 돌리려면 이 인자가 필요하다.

## 결과

- JVM 단위 테스트 66개 통과(레이아웃 파서 9개 신규). Android Lint 오류 0개, 앱 코드 경고 0개.
- 계측 테스트 14개 통과, 2개는 선택 인자가 없어 건너뜀.
- **G마켓 버거킹 쿠폰(새 양식)**: 사용처 `버거킹`(사전에 없는 이름), 종료일 `2026-09-29`,
  세 줄로 나뉜 상품명 전체 `와퍼주니어+콜라R+쉐이킹프라이스윗어니언+21치즈스틱`, 바코드 저장, 재수입 시 중복 처리 확인.
- **기존 메가MGC커피 5개**: 분리·중복 방지·종료일 유지. 상품명이 정확한 것은 5개 중 3개이며,
  나머지 2개는 OCR 오독(`골든애플`→`골든매플`, `메가MGC커피`→`메가MGC커파`)이라 확인 대상으로 표시된다.
- **가상 브랜드·배치 6종**(사전에 없는 이름, 다른 배경색, 라벨형/괄호형 배치, 축소·저품질 압축):
  상품명 정확 5건, 오독 1건은 확인 대상으로 표시. 사용처와 종료일은 6건 모두 정확.
- 실제 앱 확인: G마켓 쿠폰을 공유로 넣어 지갑에 추가되고 상품명 전체·`D-9 · 2026-09-29`가 표시되며,
  새 양식이라 `인식 결과 확인 필요`가 함께 표시됨.

집계 로그 태그: `CouponCorpus` (`multi total=5 exactTitles=3`, `generated total=6 exact=5`).

## 한계

- 같은 OCR 엔진이 두 번 모두 같은 글자를 틀리게 읽는 사례가 실제로 나왔다.
  **두 번 같은 결과가 나왔다는 사실만으로 정확하다고 판단하지 않는다.** 이때는 값을 임의로 고치지 않고 확인 대상으로 남긴다.
- 낯선 양식은 값이 맞아도 `인식 결과 확인 필요`로 표시한다. 사용자가 상세에서 확인하고 저장하면 해제된다.
- 평가 자료가 아직 실제 3장 + 가상 6장 규모다. 양식 다양성이 목표에 미치지 못한다.
- 클라우드 이미지 AI 보완 경로는 연결하지 않았다. 현재 저장소에는 해당 서버·키가 없다.
  검토 내용은 `docs/design/2026-09-19-llm-learning-review.md` 참고.
