# 스크린샷 한 장의 여러 쿠폰 분리 검증

검증일: 2026-09-19. 환경: Windows, Zulu JDK 21, FaceScope_API36 에뮬레이터(API 36).

## 구현

- 바코드를 첫 검출에서 멈추지 않고 겹치는 구간 전체에서 찾고, 같은 번호는 한 번만 남긴다.
- OCR을 줄 단위 좌표와 함께 읽어, 바코드 사이 간격에서 칸 경계를 잡고 칸 안의 글자만 그 쿠폰에 연결한다.
  같은 높이로 자르지 않는다. 바코드가 없는 잘린 카드는 쿠폰으로 만들지 않는다.
- 원본 스크린샷은 한 번만 저장하고, 쿠폰마다 `assetId` + 잘라낼 영역을 가리킨다(DB v2, 마이그레이션 제공).
- 원본·쿠폰·바코드 후보를 한 트랜잭션으로 저장한다. 같은 번호가 이미 있으면 건너뛰고, 하나도 저장되지 않으면 사본을 남기지 않는다.
- 목록·상세는 쿠폰 영역을, 코드 화면은 쿠폰 영역·바코드 확대·전체 스크린샷을 함께 보여준다.

## 실행 결과

`JAVA_HOME=C:/Program Files/Zulu/zulu-21`

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug assembleDebugAndroidTest lintDebug --console=plain
adb shell am instrument -w -e multiCouponPaths <앱 캐시 경로1>,<앱 캐시 경로2> com.couponit.app.test/androidx.test.runner.AndroidJUnitRunner
```

- 단위 테스트 55개 통과(분리 로직 10개, 파서 23개 포함). Android Lint 오류 0개.
- 계측 테스트 12개 통과, 2개는 개인 이미지 인자가 없어 건너뜀.
  - `MultiCouponImportTest`: 실제 네이버페이 교환권 화면 2장 → **쿠폰 5개**(2개 + 3개), 번호 5개 모두 다름,
    쿠폰마다 제 영역을 가리킴, 원본은 2개만 저장. 사용처 `메가MGC커피`, 종료일 `2026-12-21` 연결.
    같은 화면을 다시 담으면 **저장 0개 · 중복 5개**로 쿠폰이 늘지 않음.
  - `Migration1To2Test`: v1 DB의 쿠폰이 유지되고 원본 자산과 연결되며 영역은 비어 있음.
  - `ImportPersistenceTest`: 후보 저장 실패 시 쿠폰·원본까지 롤백. 한 이미지 안의 같은 번호는 1개만 저장.
- 실기기 DB 갱신 확인: v1 데이터가 있는 설치본에 새 APK를 덮어 설치한 뒤 실행 → 기존 쿠폰이 그대로 보이고 오류 없음.

## 수정한 문제

- **잘린 이미지 재인식**: 상세 화면 재인식이 잘라낸 이미지를 새로 읽어 가져올 때와 결과가 달랐다.
  첫 칸의 종료일을 놓치고 `[EVENT]`의 여는 대괄호를 잃었다. 원본을 읽고 좌표로 거르도록 바꿔 가져오기와 결과를 일치시켰다.
- **OCR이 숫자 사이에 넣는 공백**: 실제 인식 결과가 `2026.1 2.21`로 나와 종료일이 비었다.
  월·일 안의 공백 하나를 허용하도록 날짜 패턴을 고쳤다.
- **테스트 의존성 충돌**: `room-testing`의 스키마 파서는 kotlinx-serialization 1.8 계열로 컴파일돼 있는데
  lifecycle이 core 1.7.3을 고정해 `AbstractMethodError`가 났다. 앱에서 core를 1.8.1로 올려 맞췄다.

## 한계

- 칸 경계는 바코드 위치로 계산한다. 한 카드에 바코드가 둘이거나 간격이 불규칙하면 **확인 필요**로 표시하며,
  2열 배치처럼 좌우로 나뉜 화면은 검증하지 않았다.
- OCR은 실행마다 글자를 다르게 묶을 수 있다. 상품명의 한 글자 오인식(`골든애플`→`골든매플`, `메가MGC커피`→`메가MGC커파`)이
  실제로 나왔고, 읽은 그대로 저장한다. 사용처는 브랜드 사전으로 보정하지만 상품명은 추측으로 덮어쓰지 않는다.
- 실제 이미지와 쿠폰 번호는 저장소에 넣지 않는다. 검증은 경로를 실행 인자로 넘겨 재현한다.
